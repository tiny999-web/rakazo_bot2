# Rakazo 六人 AI 团队搭建手册

> 目标：在 Rakazo 中建立 6 个各有专职的持久 Bot，组成可互相 @mention、分工协作的团队。

## 二、前置条件（本机实测状态）

| 项 | 要求 | 本机状态 |
|---|---|---|
| Docker Engine + Compose | 必需 | 安装中/待验证 |
| Node.js | 24.15+ 或 26+（不支持 25.x） | 已装 24.22.3（nvm） |
| pnpm | 12 | 已装 12.23.0 |
| WSL2（Windows Docker 后端） | Docker Desktop 依赖 | 被安全策略拦截，需人工确认后端 |
| 模型 API | 至少一个 provider key | 已有 sensenova OpenAI-compatible 端点 |

## 三、安装 Rakazo（发布镜像路线，推荐）

在目标机器（有 Docker 的环境）执行：

```bash
mkdir -p rakazo && cd rakazo &&
curl -fsSLO https://raw.githubusercontent.com/elie222/rakazo/main/infra/compose/install-images.sh &&
bash install-images.sh
```

安装器会下载 Compose 文件、生成带随机密钥的 `.env`、启动 Rakazo。重复运行会保留已有 `.env`。

启动后打开 http://127.0.0.1:5173 ，创建账号、连接模型。本地 Docker computers 默认开启。

> 源码开发路线（备选）：`git clone https://github.com/elie222/rakazo.git` → `cp .env.example .env` → 设置数据库密码与各类密钥 → `pnpm install && pnpm sandbox:build && pnpm dev`。要求 Node 24.15+/26+、pnpm 12、Docker。

## 四、连接模型（用你自己的 sensenova 网关）

在 Web UI：`Settings → Models → Connect a model` → 选 **OpenAI-compatible**：

- **server base URL**：你的 sensenova OpenAI-compatible 端点（形如 `https://token.sensenova.cn/v1`）
- **model id**：精确模型名（如 `sensenova-6.8-flash-lite`）
- **API key**：你的 token
- **Advanced**：若需视觉能力（screenshot computer tools）勾选 **Supports images**；按需设置 request headers

也支持 OpenRouter / Anthropic / DeepSeek 等 provider：设置对应环境变量（`OPENROUTER_API_KEY` 等）或在 UI 里填 key。

## 五、创建 6 个 Bot 并注入人设

对每个角色重复以下步骤：

1. 在 Web UI 创建 Bot，命名为对应角色（如「司南 Compass」）。
2. 打开 Bot 的 **Settings**，找到 **Instructions** 字段。
3. 打开对应的 `0X-角色-*.md` 文件，把全文（从标题到结尾）复制粘贴到 Instructions。
   - 上限 20,000 字符，本手册的 6 份人设均远低于此限制。
4. 在 **Settings → Advanced → Manage other bots** 按需开启（新 Bot 默认开启，允许它管理其他 Bot、建群、改同伴的 instructions）。
5. 为 Bot 选择模型（可用上一步连接的 sensenova，也可各自不同）。
6. 保存。

> 6 份人设的「协作接口」章节已写明彼此如何配合，注入后团队天然知道彼此职责。

## 六、组建团队（Group Chat）

1. 创建一个群（通过 UI 的 group 创建，或让开启了 Manage other bots 的 Bot 用 `create_group` 工具）。
2. 把 6 个 Bot 全部加入群（一个群支持 2–10 成员，6 个正好）。
3. 在群里用 `@角色名` 指定某个 Bot 处理任务，例如：
   - `@司南 把这个想法整理成 PRD`
   - `@基石 按 PRD 实现，注意幂等`
   - `@破壁 对这次改动做边界测试`
   - `@节拍 排一下这周的交付节点`
   - `@燎原 写上线公告，别夸大`

## 七、协作模式建议

- **主链**：司南（PRD）→ 灵犀（设计）/ 基石（实现）→ 破壁（测试）→ 节拍（节奏）→ 燎原（上线传播）。
- **委派**：给司南或节拍开启 Manage other bots，它们能 `create_group`、`set_child_instructions`、`create_child_routine`，自动分工与排期。
- **互相检查**：群里让破壁复核基石的交付，让司南验收功能是否符合用户价值。
- **审批注意**：`set_child_instructions` 和 `set_child_bot_model` 在 Ask/Auto 模式下会弹审批卡，需人工确认；"Always allow" 也跳不过这两项。

## 八、关键不确定项与边界

- **WSL2 限制**：本机 `wsl.exe` 被安全策略拦截，Docker Desktop 的 WSL2 后端可能无法启动。若 Docker 引擎起不来，需人工在安全中心放行 wsl.exe，或改用 Hyper-V 后端 / 远程服务器部署。
- **GUI 限制**：本环境无法启动 GUI 程序，Web UI 的建 Bot / 建群操作需人工在桌面完成。
- **群聊 ≠ 身份隔离**：Rakazo 的团队 Bot 共享工作区、登录态与已连接账户，按"可信协作环境"评估，不要假设 Bot 之间有权限隔离。
- **模型额度**：免费模型通道（如 OpenCode Zen）有服务端额度限制，与配置无关；建议用自有 key 的 sensenova 作为默认。
